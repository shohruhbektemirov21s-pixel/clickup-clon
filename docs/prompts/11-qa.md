`backend/.coveragerc`).

route'lari (barchasi yangi/uncommitted yoki yaqinda qo'shilgan) uchun

birinchi ishi shu.

## Prompt

```
Extend QA/E2E coverage for UzWork. The Playwright suite
(frontend/e2e/) and backend pytest suite (backend/apps/*/tests.py) are
established and CI-enforced (.github/workflows/ci.yml's e2e and backend
jobs) — follow their existing patterns (frontend/e2e/fixtures.ts for auth
helpers, throttleAdvice for rate-limit-aware login) rather than inventing
a new test harness.

First, audit: for each of dashboard, ai, planner, notifications, chat
(check frontend/src/app/(app)/w/[workspaceId]/ for the full current
route list — it may have grown since this was written), confirm whether
frontend/e2e/ has ANY test touching that route. Do not assume — grep for
the route path in frontend/e2e/*.spec.ts.

For any route with zero coverage, add at minimum:
- A smoke test: authenticated user can navigate to it and it renders
  without error.
- A permission test mirroring e2c4f62's pattern: a read-only/guest/demo
  account does not see write affordances it can't use (this is the exact
  regression class that commit fixed for the list view — see
  10-security-audit.md for the security angle on the same gap, this is
  the QA angle: prove it with a test, not just a code read).

Also check: docs/adr/0009-status-modeli.md's status migration, if it has
landed, needs both backend pytest coverage (mapping-table correctness,
migration idempotency) and E2E coverage (board columns still render with
the new fixed codes) — this is exactly the kind of cross-cutting change
that's easy to under-test because no single "phase" owns it end to end.

Do not lower backend/.coveragerc's fail_under to make a red run pass —
that ratchet only moves down as real coverage goes up (see 08-devops.md).
```
